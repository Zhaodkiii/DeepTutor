# 技能、子代理与工具生态需求

## 一、模块目标

本模块负责 DeepTutor 的技能系统、子代理系统、工具注册表、MCP 工具、内置工具和社区技能导入。它是产品可扩展性的核心底座。

## 二、技能、子代理与工具生态模块结构

### 2.1 技能管理

#### 需求说明

系统需要支持 builtin skills、user skills 和外部 hub 安装的 skills。

#### 基础要求与业务规则

- skill 是目录级 playbook，不是随意字符串。
- builtin skills 只读，user skills 可编辑。
- 安装来源要可追踪。

#### 验收标准

- 能列出、读取、安装和编辑 skill。
- 技能名称和前缀规则可校验。

#### 技术细节与设计代码位置

| 职责 | 代码位置 |
| --- | --- |
| skill service | `deeptutor/services/skill/service.py` |
| skill hub 安装 | `deeptutor/services/skill/hub.py` |
| builtin skills | `deeptutor/skills/builtin/*` |

### 2.2 子代理接入

#### 需求说明

系统需要能连接本地 CLI 子代理和伙伴型子代理，并统一发现、检测和注册。

#### 基础要求与业务规则

- 子代理 backend 需要可发现。
- local CLI backend 与 partner backend 在注册表里共存但要区分。

#### 验收标准

- 可以列出可连接 backend。
- 可以检测本机可用 CLI。

#### 技术细节与设计代码位置

| 职责 | 代码位置 |
| --- | --- |
| backend registry | `deeptutor/services/subagent/registry.py` |
| backend base | `deeptutor/services/subagent/base.py` |
| partner / CLI backends | `deeptutor/services/subagent/*` |

### 2.3 工具注册与能力注册

#### 需求说明

聊天运行时需要统一的 tool registry 和 capability registry，保证工具名、能力名和导出 schema 同步。

#### 基础要求与业务规则

- 工具和 capability 的引用必须一致。
- 配置漂移要在启动期发现。
- 支持 defered tools progressive disclosure。

#### 验收标准

- 可列出工具和 capability。
- OpenAI schema 可自动生成。

#### 技术细节与设计代码位置

| 职责 | 代码位置 |
| --- | --- |
| capability registry | `deeptutor/runtime/registry/capability_registry.py` |
| tool registry | `deeptutor/runtime/registry/tool_registry.py` |
| 内置能力 | `deeptutor/runtime/bootstrap/builtin_capabilities.py` |
| 内置工具 | `deeptutor/tools/builtin/*` |

## 三、技能、子代理与工具生态模块功能

### 3.1 技能安装与读取

#### 需求说明

用户可安装社区 skill，也可以在模型运行时按需读取 skill 内容。

#### 基础要求与业务规则

- 安装包必须经过安全门。
- 大文件和非法文件类型要拒绝。

#### 验收标准

- 可以从 hub 安装 skill。
- 可以通过 read_skill 类工具读取内容。

#### 技术细节与设计代码位置

- `deeptutor/services/skill/service.py`
- `deeptutor/api/routers/skills.py`
- `deeptutor/skills/builtin/skill-creator/SKILL.md`

### 3.2 子代理连接与检测

#### 需求说明

用户可以连接本地 CLI 或伙伴 backend 作为子代理。

#### 基础要求与业务规则

- 只对本机可用 CLI 做探测。
- partner backend 不应被误判为“本机安装”。

#### 验收标准

- 检测结果能区分可用与不可用。

#### 技术细节与设计代码位置

- `deeptutor/services/subagent/registry.py`
- `deeptutor/services/subagent/process.py`
- `deeptutor/services/subagent/sessions.py`

### 3.3 工具调用与能力暴露

#### 需求说明

系统需要把工具和能力暴露给前端、CLI 和模型运行时。

#### 基础要求与业务规则

- 工具定义与 prompt hints 必须可序列化。
- 可选工具要遵守用户授权。

#### 验收标准

- Settings 页可以列出工具。
- capability 可正确挂载工具。

#### 技术细节与设计代码位置

- `deeptutor/runtime/registry/tool_registry.py`
- `deeptutor/api/routers/tools.py`
- `deeptutor/tools/*`

## 整体业务流程

```text
技能 / 子代理 / 工具被声明
  ↓
注册表加载 builtins 与 plugins
  ↓
启动时校验能力引用是否漂移
  ↓
用户或模型按需请求 tool / skill / subagent
  ↓
执行结果回到 capability 或 UI
```

## 状态模型

- skill：builtin、user、admin、hub-installed。
- subagent：可探测、可连接、运行中、失败。
- tool：内置、可切换、只读展示、coming soon。
- capability：已注册、可用、不可用、插件加载中。

## 数据与持久化

- skills 存于工作区目录。
- 子代理会话和运行状态落在服务层目录。
- 工具和 capability 主要是运行时注册，但配置可持久化到 settings。

## 错误模型

- skill 名称非法。
- 安装来源不安全。
- 子代理 backend 不可执行。
- 工具/能力引用漂移。

## 与其他模块的接口边界

- 上游：Chat、Settings、Admin、Partner、CLI、Web。
- 下游：技能存储、子代理进程、工具注册表、MCP。
- 不负责：知识库、Book、学习的核心算法。

## 测试策略

- skill 安装、读取、安全门和子代理检测要有回归测试。
- 工具/能力漂移需要启动校验测试。

## 当前实现、缺口与演进

当前生态已经很丰富，但角色较多，后续建议继续统一 manifest、schema 和授权检查的表达。
