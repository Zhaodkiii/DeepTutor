# 对话与会话运行时需求

## 一、模块目标

本模块负责一次用户对话 turn 的生命周期，包括会话创建、turn 编排、流式输出、取消、重试、恢复和 session 持久化。它是 DeepTutor 所有 capability 的共同执行壳。

## 二、对话与会话运行时模块结构

### 2.1 应用门面与 turn 请求

#### 需求说明

CLI、API 和其他适配器需要通过统一请求对象发起 turn，而不是各自拼接调用参数。

#### 基础要求与业务规则

- `TurnRequest` 必须能承载 capability、session、tools、knowledge_bases、attachments、skills 等字段。
- capability 名称要先经过解析，再进入 runtime。

#### 验收标准

- 任何入口都能复用同一套 turn 提交协议。
- session preferences 会被写回存储。

#### 技术细节与设计代码位置

| 职责 | 代码位置 |
| --- | --- |
| 稳定应用门面 | `deeptutor/app/facade.py` |
| turn 请求对象 | `deeptutor/app/facade.py` |
| 门面调用 runtime | `deeptutor/app/facade.py` |

### 2.2 单 turn 编排与流式事件

#### 需求说明

一次用户输入要经过 capability 选择、上下文封装、工具调用和事件流输出。

#### 基础要求与业务规则

- 没有 session id 时自动生成。
- capability 不存在时要发出错误事件而不是静默失败。
- turn 的流式事件必须按顺序发出。

#### 验收标准

- 能看到 SESSION、增量输出、DONE 等事件。
- 异常会转成流式错误，而不是让连接直接断掉。

#### 技术细节与设计代码位置

| 职责 | 代码位置 |
| --- | --- |
| turn 编排器 | `deeptutor/runtime/orchestrator.py` |
| StreamBus | `deeptutor/core/stream_bus.py` |
| 流式事件定义 | `deeptutor/core/stream.py` |
| 会话上下文 | `deeptutor/core/context.py` |

### 2.3 会话存储与恢复

#### 需求说明

需要持久化对话历史、当前 turn、偏好设置和会话列表，支持恢复、重命名、删除和续聊。

#### 基础要求与业务规则

- 会话存储应统一在一个 session manager 中完成。
- turn 停止或失败后要能查询当前活跃状态。
- 不同 capability 的 session 需要共享统一结构。

#### 验收标准

- 可以按列表加载 session。
- 可以取回完整消息。
- 可以删除和重命名 session。

#### 技术细节与设计代码位置

| 职责 | 代码位置 |
| --- | --- |
| 统一会话管理 | `deeptutor/services/session/unified_session_manager.py` |
| 运行时 turn 管理 | `deeptutor/services/session/turn_runtime.py` |
| 存储协议 | `deeptutor/services/session/protocol.py` |
| SQLite / PocketBase 存储 | `deeptutor/services/session/sqlite_store.py`、`deeptutor/services/session/pocketbase_store.py` |

## 三、对话与会话运行时功能

### 3.1 发起对话

#### 需求说明

用户输入后，系统需要建立 session，保存消息，并把 turn 推给正确的 capability。

#### 基础要求与业务规则

- 新会话标题通常取用户首条消息前缀。
- 允许显式传入历史记录。
- 允许启用 RAG 和 web search 等辅助能力。

#### 验收标准

- 新会话能立即收到 session id。
- 消息会写入历史。

#### 技术细节与设计代码位置

- `deeptutor/api/routers/chat.py`
- `deeptutor/app/facade.py`
- `deeptutor/services/session/*`

### 3.2 流式回复

#### 需求说明

用户应能看到增量文本，而不是只能等待一次性结果。

#### 基础要求与业务规则

- 增量 chunk 需要按顺序发送。
- 完成后必须发送最终结果。
- 来源信息在有 RAG/web 时要能回传。

#### 验收标准

- 前端能实时渲染回复。
- 来源列表可以在结果后附带返回。

#### 技术细节与设计代码位置

- `deeptutor/api/routers/chat.py`
- `deeptutor/core/stream_bus.py`
- `deeptutor/core/stream.py`

### 3.3 取消、重生成和用户补答

#### 需求说明

用户需要能取消正在进行的 turn、重试上一轮、或者在模型追问时提交答案。

#### 基础要求与业务规则

- 取消只影响当前 turn，不应破坏 session 历史。
- 重生成应该基于最后一轮 session。
- `ask_user` 类暂停需要明确的答复回注。

#### 验收标准

- 取消后不会残留错误的活跃状态。
- 重生成能复用同一 session。

#### 技术细节与设计代码位置

- `deeptutor/app/facade.py`
- `deeptutor/services/session/turn_runtime.py`
- `deeptutor/tools/ask_user.py`

## 整体业务流程

```text
用户输入
  ↓
创建或恢复 session
  ↓
写入 user 消息
  ↓
解析 capability 和辅助参数
  ↓
运行 capability
  ↓
流式输出 chunk / status / error
  ↓
结束后写入 session 和 turn 状态
```

## 状态模型

- 会话状态：新建、活跃、空会话、已删除。
- turn 状态：准备中、流式输出中、等待用户补答、已取消、已完成、失败。
- 消息状态：用户消息、助手消息、工具消息、系统消息。

## 数据与持久化

- session 列表和消息历史由 session store 管理。
- session preferences 会保存语言、Notebook 引用和历史引用。
- 活跃 turn 状态由 turn runtime 和 stream bus 维护。

## 错误模型

- 不存在的 session 返回 404 或自动新建。
- capability 不存在时返回可读错误。
- 流式过程中异常会转成 error event。
- 取消与并发修改要防止回写旧状态。

## 与其他模块的接口边界

- 上游：CLI、WebSocket、REST API、SDK。
- 下游：CapabilityRegistry、ToolRegistry、LLM、RAG、Book、Learning、Memory、Partner。
- 不负责：领域内容本身的规则，只负责 turn 编排和会话状态。

## 测试策略

- `tests/services/session/*` 已覆盖多项存储和 runtime 行为。
- 需要保留 turn cancel、regenerate 和补答链路的回归测试。

## 当前实现、缺口与演进

当前已经有统一会话管理和流式总线，但 session 持久化实现仍分布在不同 store，后续可以继续收敛接口和错误模型。

## 整体验收标准

- [ ] 任意入口都能完成一次 turn。
- [ ] session 能创建、读取、重命名、删除。
- [ ] 流式输出和错误输出可观测。
- [ ] 取消、重试和补答不破坏历史。
