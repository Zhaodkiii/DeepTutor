# 伙伴与外部渠道需求

## 一、模块目标

本模块负责 DeepTutor 的伙伴（Partners）和 IM 渠道接入。它让一个伙伴可以运行在服务器进程里，再把消息分发到 Slack、Telegram、WeCom、Feishu、Discord、WhatsApp、Matrix 等通道。

## 二、伙伴与外部渠道模块结构

### 2.1 伙伴生命周期

#### 需求说明

系统需要能创建、启动、停止、重载和持久化伙伴实例。

#### 基础要求与业务规则

- 每个伙伴都有独立 workspace。
- 伙伴运行在同一进程中，但任务和会话要隔离。
- 伙伴的配置要能隐藏敏感字段。

#### 验收标准

- 可以列出伙伴。
- 可以自动启动伙伴。
- 可以重载伙伴配置。

#### 技术细节与设计代码位置

| 职责 | 代码位置 |
| --- | --- |
| 伙伴管理器 | `deeptutor/services/partners/manager.py` |
| 伙伴运行器 | `deeptutor/services/partners/runtime.py` |
| 伙伴会话存储 | `deeptutor/services/partners/sessions.py` |
| 伙伴 workspace | `deeptutor/services/partners/workspace.py` |

### 2.2 渠道管理

#### 需求说明

伙伴需要把输出消息按通道送到不同 IM 平台，并支持重试、去重和流式合并。

#### 基础要求与业务规则

- 每个渠道有自己的启停和配置。
- 重复回复要抑制。
- 流式增量需要合并，避免刷屏。

#### 验收标准

- 消息可以从队列送到多个渠道。
- 失败时有重试策略。

#### 技术细节与设计代码位置

| 职责 | 代码位置 |
| --- | --- |
| 渠道管理器 | `deeptutor/partners/channels/manager.py` |
| 渠道基类 | `deeptutor/partners/channels/base.py` |
| 渠道实现 | `deeptutor/partners/channels/*` |
| 消息总线 | `deeptutor/partners/bus/*` |

### 2.3 伙伴与前端入口

#### 需求说明

用户需要在 Web 中看到伙伴列表并进入会话。

#### 基础要求与业务规则

- 页面和后端配置必须保持一致。
- 伙伴能力应和工具、模型、权限联动。

#### 验收标准

- `partners` 页面可以打开。

#### 技术细节与设计代码位置

| 职责 | 代码位置 |
| --- | --- |
| Partners 页面 | `web/app/(workspace)/partners/page.tsx` |
| Partners API | `deeptutor/api/routers/partners.py` |
| 伙伴服务聚合 | `deeptutor/services/partners/__init__.py` |

## 三、伙伴与外部渠道模块功能

### 3.1 创建与管理伙伴

#### 需求说明

支持创建伙伴、设置人格和渠道，并长期运行。

#### 基础要求与业务规则

- 伙伴 id 必须可 URL 安全。
- 支持 backup LLM selection。

#### 验收标准

- 伙伴配置可持久化且可重启恢复。

#### 技术细节与设计代码位置

- `deeptutor/services/partners/manager.py`
- `deeptutor/api/routers/partners.py`

### 3.2 渠道消息分发

#### 需求说明

伙伴的输出需要按渠道送达用户。

#### 基础要求与业务规则

- 不同渠道的 delivery flag 独立。
- 渠道启动失败不应影响其他渠道。

#### 验收标准

- 至少能把消息分发到已启用渠道。

#### 技术细节与设计代码位置

- `deeptutor/partners/channels/manager.py`
- `deeptutor/partners/bus/queue.py`
- `deeptutor/partners/bus/events.py`

### 3.3 伙伴对话回放与恢复

#### 需求说明

刷新页面或断线后，伙伴会话应能重新订阅并恢复流。

#### 基础要求与业务规则

- LiveTurn 要能缓存事件。
- 恢复时不能丢失已输出内容。

#### 验收标准

- 中断后可继续观察同一 turn。

#### 技术细节与设计代码位置

- `deeptutor/services/partners/manager.py`
- `deeptutor/services/partners/runtime.py`

## 整体业务流程

```text
创建伙伴
  ↓
初始化 workspace / soul / session
  ↓
启动 PartnerRunner
  ↓
将输出路由到 MessageBus
  ↓
ChannelManager 按平台分发
  ↓
消息送达或重试
```

## 状态模型

- 伙伴：未启动、运行中、重载中、停止中、异常。
- 渠道：已配置、已启用、启动失败、发送失败、重试中。
- LiveTurn：进行中、已结束、可回放。

## 数据与持久化

- 伙伴 workspace 存放在 `data/partners/{partner_id}/`。
- 渠道配置和会话状态会落盘。

## 错误模型

- 渠道 SDK 不可用。
- 配置包含敏感字段或非法值。
- 重载期间出错。
- 重复消息发送。

## 与其他模块的接口边界

- 上游：multi_user、API、UI、skills、tools。
- 下游：IM SDK、消息总线、伙伴 workspace、LLM。
- 不负责：知识库和学习闭环的业务逻辑。

## 测试策略

- 伙伴生命周期、消息去重和渠道重试需要测试。
- 需要保留 refresh/reload 场景的回归测试。

## 当前实现、缺口与演进

当前伙伴体系已能覆盖多渠道和回放，但渠道众多，后续应继续减少重复配置和提升监控可读性。

## 整体验收标准

- [ ] 伙伴可创建和运行。
- [ ] 渠道可启停并送达消息。
- [ ] 断线可恢复。
- [ ] 敏感配置可脱敏。
