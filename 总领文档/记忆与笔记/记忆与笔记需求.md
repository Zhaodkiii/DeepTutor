# 记忆与笔记需求

## 一、模块目标

本模块负责 DeepTutor 的三层记忆、Notebook 记录、trace 追踪和记忆迁移。它让“本次对话发生了什么、系统学到了什么、用户保存了什么”都能落到可编辑的数据结构里。

## 二、记忆与笔记模块结构

### 2.1 三层记忆

#### 需求说明

系统需要把原始事件、结构化摘要和长期记忆分开管理。

#### 基础要求与业务规则

- L1 负责原始 trace，L2/L3 负责文档化记忆。
- 记忆写入要支持原子更新和并发保护。
- 旧版 PROFILE / SUMMARY 需要兼容迁移。

#### 验收标准

- 能读取 L2/L3 记忆文档。
- 能把 L1 事件沉淀到更高层记忆。

#### 技术细节与设计代码位置

| 职责 | 代码位置 |
| --- | --- |
| 记忆总入口 | `deeptutor/services/memory/__init__.py` |
| 记忆存储 | `deeptutor/services/memory/store.py` |
| trace | `deeptutor/services/memory/trace.py` |
| 文档解析 | `deeptutor/services/memory/document.py` |
| consolidator | `deeptutor/services/memory/consolidator/*` |

### 2.2 Notebook

#### 需求说明

Notebook 需要保存来自 chat、solve、research、co-writer 等流程的记录。

#### 基础要求与业务规则

- Notebook 文件必须和 Web / CLI 共用。
- summary 写入前要清理模型私有思维痕迹。
- 笔记记录需要支持分类与附带知识库来源。

#### 验收标准

- 可以创建、列出、更新 notebook。
- 可以按 record 写入和读取。

#### 技术细节与设计代码位置

| 职责 | 代码位置 |
| --- | --- |
| Notebook manager | `deeptutor/services/notebook/service.py` |
| Notebook API | `deeptutor/api/routers/notebook.py` |
| Notebook tool | `deeptutor/tools/list_notebook.py`、`deeptutor/tools/write_note.py` |

### 2.3 记忆与笔记的界面入口

#### 需求说明

用户需要通过专门页面查看 memory 和 notebook。

#### 基础要求与业务规则

- 前端页面应展示当前状态而不是空壳。
- memory 与 notebook 的入口应和数据目录一一对应。

#### 验收标准

- 页面能看到记忆和笔记列表。

#### 技术细节与设计代码位置

| 职责 | 代码位置 |
| --- | --- |
| Memory 页面 | `web/app/(utility)/memory/page.tsx` |
| Notebook 页面 | `web/app/(utility)/notebook/page.tsx` |
| Space / 关联界面 | `web/app/(utility)/space/page.tsx` |

## 三、记忆与笔记模块功能

### 3.1 记录对话与事件

#### 需求说明

聊天 turn 产生的关键信息要能进入 L1 trace。

#### 基础要求与业务规则

- trace 需要可追加写入。
- 事件应能被后续聚合。

#### 验收标准

- 可以看到按 surface 组织的 trace 记录。

#### 技术细节与设计代码位置

- `deeptutor/services/memory/trace.py`
- `deeptutor/services/memory/store.py`

### 3.2 汇总 L2 / L3 记忆

#### 需求说明

系统要能把低层事件合成文档化记忆。

#### 基础要求与业务规则

- 更新应该是原子性的。
- 合并时要避免重复偏好项。

#### 验收标准

- 更新后文档格式仍合法。

#### 技术细节与设计代码位置

- `deeptutor/services/memory/consolidator/*`
- `deeptutor/services/memory/store.py`

### 3.3 保存 Notebook 记录

#### 需求说明

用户可把对话、研究、题目或写作结果保存到 Notebook。

#### 基础要求与业务规则

- 记录类型要明确。
- summary 写入前要去掉思维链痕迹。

#### 验收标准

- Notebook 记录可创建、更新、删除。

#### 技术细节与设计代码位置

- `deeptutor/services/notebook/service.py`
- `deeptutor/api/routers/notebook.py`

## 整体业务流程

```text
对话 / 写作 / 研究产生事件
  ↓
L1 trace 追加
  ↓
用户或系统触发 L2/L3 consolidate
  ↓
生成可读记忆文档
  ↓
Notebook 可选择保存相关结果
  ↓
前端页面展示
```

## 状态模型

- L1：原始事件流。
- L2：surface 级记忆文档。
- L3：长期摘要与偏好。
- Notebook：空、已创建、含记录、已更新、已删除。

## 数据与持久化

- 记忆文件位于 `data/memory/`。
- Notebook 文件位于 `data/user/workspace/notebook/`。
- 迁移逻辑会把 v1 memory 文件归档。

## 错误模型

- 写入冲突。
- 文档解析失败。
- 旧数据格式迁移失败。
- 重复偏好写入。

## 与其他模块的接口边界

- 上游：Chat、Learning、Co-writer、Partner、Tools。
- 下游：记忆文件、Notebook 文件、trace/snapshot 存储。
- 不负责：学习评分和知识库检索的主逻辑。

## 测试策略

- `tests/services/session/*` 中有与记忆和附件协作的验证。
- 记忆合并、迁移和重复偏好去重需要单独回归测试。

## 当前实现、缺口与演进

记忆子系统已经从旧的单文件服务演进为三层体系，后续重点是统一 L2/L3 的编辑体验和 UI 反馈。

## 整体验收标准

- [ ] L1/L2/L3 可分别读写。
- [ ] Notebook 可持久化。
- [ ] 迁移逻辑可运行。
- [ ] 记忆写入不会重复污染。
