# 学习与掌握需求

## 一、模块目标

本模块负责 DeepTutor 的学习进度、掌握度、测验评分、错误记录、间隔复习和 Mastery Path 流程。它把“做题、纠错、复习、升级”连成一条闭环。

## 二、学习与掌握模块结构

### 2.1 学习进度与模块编排

#### 需求说明

系统需要按 book 或课程维护学习进度，并能把知识点组织成可运行模块。

#### 基础要求与业务规则

- 学习模块可以替换，替换时要清理旧知识点状态。
- 进度里必须能保存当前模块、当前 stage、知识点类型和复习队列。

#### 验收标准

- 可以加载或新建进度。
- 可以替换模块而不残留旧状态。

#### 技术细节与设计代码位置

| 职责 | 代码位置 |
| --- | --- |
| 学习模型 | `deeptutor/learning/models.py` |
| 学习服务 | `deeptutor/learning/service.py` |
| 学习存储 | `deeptutor/learning/storage.py` |

### 2.2 评分、错误与掌握度

#### 需求说明

回答要能被判定对错，并沉淀为掌握度和错误记录。

#### 基础要求与业务规则

- 没有预期答案时，评分默认失败关闭。
- 错误记录需要支持 active、retrying、graduated 等状态。
- 掌握度应可由历史尝试推导。

#### 验收标准

- 评分后能更新掌握度。
- 错误记录能随正确回答升级状态。

#### 技术细节与设计代码位置

| 职责 | 代码位置 |
| --- | --- |
| 评分策略 | `deeptutor/learning/grading.py` |
| 掌握度计算 | `deeptutor/learning/mastery.py` |
| 学习服务 | `deeptutor/learning/service.py` |

### 2.3 间隔复习与待答问题

#### 需求说明

系统需要把掌握度、错误记录和复习时间合并成可执行的复习队列。

#### 基础要求与业务规则

- 间隔复习要支持不同知识类型不同曲线。
- 同时只应维护一个待答问题，避免模型“记错答案”。

#### 验收标准

- 到期任务可以被取出。
- pending question 可以跨 turn 持久化。

#### 技术细节与设计代码位置

| 职责 | 代码位置 |
| --- | --- |
| 复习调度 | `deeptutor/learning/scheduler.py` |
| 待答问题 | `deeptutor/learning/models.py` |
| 问题银行与接口 | `deeptutor/api/routers/question.py`、`deeptutor/api/routers/mastery_path.py`、`deeptutor/api/routers/quiz_judge.py` |

## 三、学习与掌握模块功能

### 3.1 诊断与分模块学习

#### 需求说明

Mastery Path 先诊断，再按知识点讲解、检核、练习和复习。

#### 基础要求与业务规则

- 学习 stage 必须有清晰的前后关系。
- 旧版 stage 名称需要兼容。

#### 验收标准

- 能从诊断阶段流转到 explain / practice / review / completed。

#### 技术细节与设计代码位置

- `deeptutor/learning/models.py`
- `deeptutor/learning/service.py`

### 3.2 题目评分与错误管理

#### 需求说明

答题后需要自动评分并记录错误类型。

#### 基础要求与业务规则

- 多次错误应形成 retry history。
- 正确答案应能让错误记录毕业。

#### 验收标准

- 能看到每题的对错记录和错误类型。

#### 技术细节与设计代码位置

- `deeptutor/learning/grading.py`
- `deeptutor/learning/service.py`
- `deeptutor/api/routers/quiz_judge.py`

### 3.3 间隔复习

#### 需求说明

系统要根据知识类型安排后续复习时间。

#### 基础要求与业务规则

- 不同知识类型的 interval 序列不同。
- 连续正确和连续错误会影响下次复习时间。

#### 验收标准

- 复习队列可自动重建。

#### 技术细节与设计代码位置

- `deeptutor/learning/scheduler.py`
- `deeptutor/learning/service.py`

## 整体业务流程

```text
创建或加载学习进度
  ↓
初始化模块与知识点
  ↓
进入 diagnostic / explain / practice / review
  ↓
记录答题结果
  ↓
更新掌握度与错误记录
  ↓
重建复习队列
  ↓
持久化进度
```

## 状态模型

- 学习阶段：diagnostic、explain、feynman_check、practice、error_diagnosis、review、completed。
- 知识类型：memory、concept、procedure、design。
- 错误状态：active、retrying、review、graduated。

## 数据与持久化

- 进度按 `book_id` 持久化。
- 会保存模块、知识点、掌握度、复习状态、错误记录和待答题。

## 错误模型

- 题目无 expected answer。
- stage 兼容失败。
- 学习模块替换后旧状态清理不完整。

## 与其他模块的接口边界

- 上游：Book、Chat、Space、Question、Quiz、Notebook。
- 下游：学习存储、调度器、评分器、掌握度模型。
- 不负责：题目来源本身的生成逻辑。

## 测试策略

- `deeptutor/learning/tests/*` 已覆盖评分、策略、存储、API 和 mastery 工具。
- 需要继续覆盖 stage 转移、错误毕业和复习队列重建。

## 当前实现、缺口与演进

当前实现已经形成学习闭环，但 score / stage / review 的边界还可以继续抽象，便于未来替换更复杂的教学策略。

## 整体验收标准

- [ ] 学习进度可创建和恢复。
- [ ] 答题后能更新掌握度和错误记录。
- [ ] 复习队列可自动生成。
- [ ] 旧 stage 数据可兼容。
