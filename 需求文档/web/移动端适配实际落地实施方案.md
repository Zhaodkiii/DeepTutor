# DeepTutor Web 移动端适配实际落地实施方案

## 1. 实施原则

本方案用于把移动端底部 Tab 与右侧控制面板真正落到 DeepTutor Web 代码中。核心原则是：

```text
新增移动端壳层，不重写桌面端。
移动端组件只在 <768px 显示。
桌面端组件只在 >=768px 显示。
业务页面先不大改，只做必要的安全区域和溢出修正。
```

## 6. 权限处理

桌面端 `SidebarShell.tsx` 里使用：

```tsx
const { has } = useCapabilityAccess();
```

移动端应保持一致。否则移动端会出现桌面端被锁定、手机端却可进入的权限不一致问题。

底部 Tab 权限逻辑：

```tsx
const locked = item.requires ? !has(item.requires) : false;
```

锁定态交互建议：

- 不跳转。
- 图标透明度降低。
- 显示小锁图标。
- 点击时展示 toast 或轻提示：`请联系管理员开通访问权限`。

代码样本：

```tsx
if (locked) {
  return (
    <button
      key={item.href}
      type="button"
      aria-disabled="true"
      className="relative flex min-w-0 flex-col items-center justify-center gap-0.5 rounded-[10px] text-[10.5px] text-[var(--muted-foreground)]/40"
      onClick={() => {
        // 可接入现有 Toast 机制；如果没有统一 API，可先不提示。
      }}
    >
      <item.icon size={20} strokeWidth={1.7} />
      <Lock size={10} className="absolute right-3 top-2" />
      <span className="max-w-full truncate">{item.shortLabel ?? item.label}</span>
    </button>
  );
}
```

## 7. Layout 接入方案

### 7.1 Workspace Layout

目标文件：

```text
web/app/(workspace)/layout.tsx
```

当前职责：

- 包裹 `CapabilityAccessProvider`
- 包裹 `UnifiedChatProvider`
- 渲染 `WorkspaceSidebar`
- 渲染主内容

推荐改造后结构：

```tsx
import WorkspaceSidebar from "@/components/sidebar/WorkspaceSidebar";
import { MobileAppShell } from "@/components/mobile/MobileAppShell";
import { CapabilityAccessProvider } from "@/components/access/CapabilityAccessContext";
import CapabilityGate from "@/components/access/CapabilityGate";
import { UnifiedChatProvider } from "@/context/UnifiedChatContext";

export default function WorkspaceLayout({
  children,
}: Readonly<{
  children: React.ReactNode;
}>) {
  return (
    <CapabilityAccessProvider>
      <UnifiedChatProvider>
        <div className="flex h-dvh overflow-hidden md:h-screen">
          <div className="hidden md:block">
            <WorkspaceSidebar />
          </div>

          <main className="hidden flex-1 overflow-hidden bg-[var(--background)] md:block">
            <CapabilityGate>{children}</CapabilityGate>
          </main>

          <div className="block min-w-0 flex-1 bg-[var(--background)] md:hidden">
            <MobileAppShell>
              <CapabilityGate>{children}</CapabilityGate>
            </MobileAppShell>
          </div>
        </div>
      </UnifiedChatProvider>
    </CapabilityAccessProvider>
  );
}
```

注意点：

- 使用 `h-dvh` 优先解决 iOS Safari 地址栏变化导致的高度抖动。
- `WorkspaceSidebar` 用 `hidden md:block` 包裹，保证手机端不渲染桌面侧栏。
- 移动端 `MobileAppShell` 放在 `CapabilityGate` 外还是内都可以，推荐 Shell 外、内容内，这样无权限页面仍保留移动端导航。

### 7.3 为什么不要改 RootLayout

不建议直接在 `app/layout.tsx` 加移动端导航：

- 登录页、注册页不应该出现底部 Tab。
- 管理端可能有独立信息架构。
- `workspace` 和 `utility` 已经是业务区布局边界，接入更安全。

## 8. MobileAppShell 详细方案

目标文件：

```text
web/components/mobile/MobileAppShell.tsx
```

职责：

- 管理 `drawerOpen`。
- 渲染右上角设置按钮。
- 渲染可滚动页面容器。
- 渲染底部 Tab。
- 渲染右侧控制面板。
- 在 drawer 打开时锁定页面滚动。

推荐实现：

```tsx
"use client";

import { useEffect, useState } from "react";
import { Settings } from "lucide-react";
import { MobileBottomTabs } from "@/components/mobile/MobileBottomTabs";
import { MobileControlDrawer } from "@/components/mobile/MobileControlDrawer";

export function MobileAppShell({ children }: { children: React.ReactNode }) {
  const [drawerOpen, setDrawerOpen] = useState(false);

  useEffect(() => {
    if (!drawerOpen) return;

    const onKeyDown = (event: KeyboardEvent) => {
      if (event.key === "Escape") setDrawerOpen(false);
    };

    document.addEventListener("keydown", onKeyDown);
    return () => document.removeEventListener("keydown", onKeyDown);
  }, [drawerOpen]);

  return (
    <div className="relative h-dvh min-w-0 overflow-hidden bg-[var(--background)]">
      <button
        type="button"
        onClick={() => setDrawerOpen(true)}
        className="fixed right-3 top-[max(env(safe-area-inset-top),10px)] z-40 flex h-10 w-10 items-center justify-center rounded-full border bg-[var(--background)]/95 text-[var(--foreground)] shadow-sm backdrop-blur transition-colors active:bg-[var(--accent)] md:hidden"
        aria-label="打开控制面板"
        aria-expanded={drawerOpen}
      >
        <Settings size={21} strokeWidth={1.8} />
      </button>

      <div className="h-full min-w-0 overflow-hidden pb-[calc(72px+env(safe-area-inset-bottom))]">
        {children}
      </div>

      <MobileBottomTabs />
      <MobileControlDrawer open={drawerOpen} onClose={() => setDrawerOpen(false)} />
    </div>
  );
}
```

## 9. 底部 Tab 详细方案

### 9.1 激活态算法

使用 `usePathname()`：

```tsx
const active = item.match.some((prefix) => pathname === prefix || pathname.startsWith(`${prefix}/`));
```

不要只用 `startsWith("/book")` 的裸判断，以免未来出现 `/bookmark` 这类路径误匹配。

推荐函数：

```tsx
function isRouteActive(pathname: string, prefixes: string[]) {
  return prefixes.some((prefix) => {
    return pathname === prefix || pathname.startsWith(`${prefix}/`);
  });
}
```

### 9.2 主页特殊逻辑

桌面端点击 Home 会触发 `onNewChat()` 并跳转 `/home`。移动端如果需要完全一致，应让 `MobileAppShell` 接收可选 `onHomeClick`。

第一期建议：

```text
点击主页仅跳转 /home，不强制创建新会话。
```

原因：

- 移动端底部 Tab 是导航，不是“新建会话”按钮。
- 强制新建可能导致用户在手机端误触丢失当前上下文。

如果产品希望与桌面一致，则在 `WorkspaceLayout` 给 `MobileAppShell` 注入 `onHomeClick`，调用 `newSession()`。

### 9.3 布局尺寸

建议 class：

```tsx
className="fixed inset-x-0 bottom-0 z-40 border-t bg-[var(--background)]/95 px-1.5 pb-[max(env(safe-area-inset-bottom),6px)] pt-1.5 backdrop-blur md:hidden"
```

内部：

```tsx
className="grid h-14 grid-cols-6 gap-1"
```

单项：

```tsx
className="flex min-w-0 flex-col items-center justify-center gap-0.5 rounded-[10px] text-[10.5px] leading-none"
```

### 9.4 文案溢出策略

底部 Tab 的最长文案是“智能体”。建议所有文案最多 3 个中文字符：


如果国际化为英文，建议使用：



## 11. 安全区域与滚动方案

### 11.1 全局高度

当前 `globals.css` 中：

```css
html,
body {
  height: 100%;
  overflow: hidden;
}
```

因此移动端不能依赖 body 滚动，需要让页面内部容器滚动。移动端 shell 应使用：

```tsx
<div className="h-dvh overflow-hidden">
  <div className="h-full overflow-hidden pb-[calc(72px+env(safe-area-inset-bottom))]">
    {children}
  </div>
</div>
```

### 11.2 页面内部滚动

如果某个页面本身已经使用 `overflow-y-auto`，只需要保证底部 padding 足够。

推荐移动端页面容器统一类名：

```tsx
className="h-full min-w-0 overflow-y-auto px-4 pb-[calc(88px+env(safe-area-inset-bottom))] pt-14 md:pb-0 md:pt-0"
```

但不要全局强行给所有页面加 `overflow-y-auto`，否则 Chat、编辑器、双栏页面可能出现双滚动。

### 11.3 Chat 输入框避让

Chat 页面是最高风险页。建议优先查找以下组件：

```bash
rg "textarea|send|composer|input" web/components/chat web/app -n
```

处理策略：

```text
如果 Chat 输入框 fixed bottom-0：
  移动端改为 bottom: calc(64px + env(safe-area-inset-bottom))

如果 Chat 输入框在 flex 底部：
  父容器增加移动端 pb-[72px]

如果消息列表滚动到底：
  消息列表底部增加 pb-[96px]
```

样本：

```tsx
className="bottom-[calc(64px+env(safe-area-inset-bottom))] md:bottom-0"
```

## 20. 开发注意事项

### 20.1 不要使用 `window.innerWidth` 控制首屏渲染

原因：

- 容易造成 SSR 与客户端 hydration 不一致。
- Tailwind 响应式 class 已足够解决显示隐藏。

推荐：

```tsx
className="md:hidden"
className="hidden md:block"
```

### 20.2 不要让 Drawer 永久占布局宽度

Drawer 必须使用 fixed/absolute overlay，不参与主页面 layout：

```tsx
className="fixed inset-0 z-50"
```

### 20.3 不要把移动端 Tab 放进每个页面

Tab 属于布局壳层，应该在 layout 接入。如果放进每个页面，会导致：

- 重复代码。
- 状态不一致。
- 部分页面遗漏。
- 后续维护困难。

### 20.4 不要在全局 CSS 覆盖所有 main

避免类似：

```css
main {
  padding-bottom: 80px;
}
```

这会影响桌面端和不需要底部导航的页面。应使用移动端 shell 或页面级 class。

### 20.5 注意 iOS Safari 键盘

iOS Safari 键盘弹起时，`100vh` 容易不准。建议：

```tsx
className="h-dvh"
```

必要时对输入区使用：

```css
padding-bottom: env(safe-area-inset-bottom);
```

## 22. 结论

实际落地时，最稳妥的路径是先做独立移动端组件，再在 `workspace` 与 `utility` 两个 layout 中用响应式 class 接入。这样移动端拥有独立导航体验，桌面端继续使用现有 Sidebar，风险集中在两个 layout 文件和新增组件中，便于测试、回滚和后续扩展。
